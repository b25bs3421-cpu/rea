About this site

Generated, not written by hand

Every number, name and table on this site comes from the repository at build time: a catalog snapshot, the Markdown sources, and two analyses run against the bundled sample. Here is the whole pipeline, including what it cannot do.

01 · pipeline

Four steps, all in the repository

Nothing is fetched from the network, and nothing below is hand-maintained except the prose on this page and in the pages' introductions.

Step 1

Snapshot

npm run workbench:data reads the MCP contract catalog, product catalog, docs, README and source tree into workbench/data/.

Step 2

Capture

npm run site:capture runs the two workflows against the bundled sample and stores the Evidence plus the projections in site/data/.

Step 3

Render

npm run site:build renders static HTML from those files into site/public/ — no framework, no bundler, no runtime.

Step 4

Serve

npm run site:serve previews the output on port 5181. The public/ folder deploys to any static host.

rebuild everything 
npm run workbench:data   # refresh the catalog snapshot
npm run site:capture     # re-run the two sample analyses
npm run site:build       # render site/public
npm run site:serve       # preview at http://localhost:5181

04 · boundaries

Deliberate limits

Each of these is a decision, not an oversight.

Static output 01

No server, no database and no analytics. The explorer reads a JSON island embedded in the page.

Captured data 02

The two datasets are frozen at capture time. Live runs live in the Workbench console, which executes the same CLI in your checkout.

Engine-free 03

No Hopper, Ghidra or IDA here, so native-binary demos would be dishonest. Those paths are documented and indexed, not simulated.

Docs stay in place 04

Documents are indexed, not mirrored. One source of truth beats a copy that rots.

No telemetry 05

No cookies, no third-party scripts, no fonts fetched at runtime.

Provenance first 06

Every figure can be traced to a dataset digest or an Evidence id listed on this page.
